# 实操案例与代码示例：缓存优先 RAG 客服应答

## 案例 1：同一个问题问两遍，第二遍零成本秒回

**第一遍**（缓存未命中，走完整 RAG）：

```
用户：你们支持7天无理由退货吗？
decompose_query → 拆出标准问句"退货政策-无理由退货期限"
Search LangCache → 未命中
search_node1（Redis 向量检索）→ 命中 FAQ#12"自签收起7天内可无理由退货，需保持吊牌完整…"
synthesize_response → "您好，我们支持自签收之日起 7 天无理由退货，商品需保持吊牌完好…"
evaluate_quality → 0.92 分 ✅ → Save to LangCache
耗时 4.2s，消耗 OpenAI tokens ≈ 1,800
```

**第二遍**（用户换个说法问）：

```
用户：买错了还能退不
Search LangCache → 语义命中（相似度 0.94）→ 直接返回缓存答案
耗时 0.6s，tokens = 0
```

**月度账**：假设 60% 命中率 → API 成本直降六成，P95 响应从 4s 降到 1s 内。这就是"缓存优先"架构的全部意义。

### 2. 答案质量评分提示词（evaluate_quality 节点）

```
给客服答案打分（0-1，两位小数）：
- 0.9+：直接解决问题且语气得体
- 0.7-0.89：能解决但啰嗦/缺一个关键细节
- <0.7：答非所问、含糊或与知识库矛盾
只输出数字。
用户问题：{{question}}
知识库片段：{{context}}
候选答案：{{answer}}
```

低于 0.8 → 走 increase iteration 重写（上限 2 次），这是"低分重试"支线的开关。

### 3. Redis Stack 快速自检（灌库后验证向量索引建好了）

```bash
docker exec -it redis redis-cli FT.INFO idx
# 关注 NUMDOCS 是否等于你的 FAQ 条数；为 0 = 灌库支线没跑
```

## 案例 2（进阶）：知识缺口自动发现——客服最常问但库里没有的，自动出 FAQ 草稿

场景：缓存未命中 + 低分重试仍失败 = 知识库覆盖不到的真缺口。把这些"失败样本"
攒起来聚类，让 AI 起草新 FAQ，人工审核入库——知识库进入**自我生长**循环。

**数据流**：

```
低分重试后仍 <0.8 的问题 → 存"缺口表"（时间/问题/失败答案/是否转人工）
每周一 9:00 → 聚类 Code（简化：关键词分组）
→ LLM 起草：{标准问题, 标准答案草稿, 依据(转人工记录里客服怎么答的)}
→ 写"FAQ 审核表" → 飞书/邮件通知客服主管 → 人工改完 → 复制进知识库 Sheets
→ 下周缓存与检索自动生效
```

**缺口聚类 Code 节点（轻量版：按关键词桶）**：

```javascript
const rows = $input.all().map(i => i.json);
const BUCKETS = { 退换: /退|换|售后/, 物流: /发货|物流|快递|几天/, 发票: /发票|开票|报销/, 账号: /登录|密码|账号/ };
const out = {};
for (const r of rows) {
  const q = r['问题'] ?? '';
  const k = Object.entries(BUCKETS).find(([, re]) => re.test(q))?.[0] ?? '其他';
  out[k] ??= []; out[k].push(q);
}
return Object.entries(out).map(([k, qs]) => ({ json: {
  类别: k, 数量: qs.length, 样例: qs.slice(0, 3) } }));
```

**FAQ 起草提示词**：

```
你是客服知识库编辑。输入：某类别的用户原话样例 + 历史人工答复（如有）。
输出草稿（可直接进知识库的格式）：
{question: "规范化后的标准问句", answer: "标准答案：口径与人工答复一致，30-80字，含边界条件"}
没有人工答复依据的，answer 写"待补充依据"，禁止编政策。
```

**循环价值**：缺口表数量就是知识库健康度 KPI——它应当逐月下降；新 FAQ 上线后该类未命中率次周即肉眼可见地掉。
